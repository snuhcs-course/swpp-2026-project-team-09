## 요약

- **P6 통과는 4/192 실행(2.1%)이고, 세 번 다 통과한 케이스는 64개 중 1개(`p6-common-small-talk`)입니다.** threshold 9개 중 M4만 통과합니다. M4는 도서관 카드를 보일 도구가 없어서 통과한 것입니다.
- 192개 답 모두 HTTP 200이고, STEP_LIMIT, TIMEOUT, ERROR는 없습니다. 도서관 카드는 192개 답 중 한 장도 없습니다.
- 거절 15케이스(45실행)는 모두 카드 없이 답했고 43실행이 거절했지만, 라벨이 요구한 이유("미구현", "현장" 등)를 말하지 않아 모두 실패했습니다. 모델은 "공간 예약은 아직 지원하지 않아요"라고 한 가지로 거절합니다.
- P19 점검 run 한 번은 known failure를 뺀 통과 55/64(85.9%), 대체 케이스를 빼면 53/60입니다. P05 R1의 세 실행은 56, 57, 58/64(54, 55, 56/60)입니다.
- 비용은 P6 USD 0.41, P19 USD 0.36으로 기록된 것은 USD 0.77입니다. P4, P5, large-world-v1은 시작했다가 PM의 결정으로 멈췄고, 결과 파일 없이 약 USD 1.5–2.2를 썼습니다(아래 "멈춘 run").

## 실패 읽기

모델은 도서관 요청을 거의 모두 "아직 지원하지 않아요"라는 한 가지 거절로 받았습니다. 이 커밋의 채팅 규칙대로이고, 라벨은 티켓 07 뒤의 동작을 기대하므로 대부분의 케이스가 떨어지는 것은 예정된 결과입니다.

**통과한 실행 4개.**

| 케이스                     | 통과 | 왜                                                                                                                          |
| -------------------------- | ---- | --------------------------------------------------------------------------------------------------------------------------- |
| `p6-common-small-talk`     | 3/3  | 도서관에 관한 잡담에 도구 없이 CHAT으로 답하라는 라벨입니다. 도서관 도구가 필요 없는 유일한 케이스라 지금 코드로도 맞습니다 |
| `p6-bookings-did-i-return` | 1/3  | "반납했어?"에 카드 없이 CHAT으로 답하라는 라벨입니다. 세 실행 모두 카드 없이 답했고, 한 실행만 라벨의 문구를 썼습니다       |

**실패의 모양.**

- **카드가 필요한 23케이스**(공간, 조건, 단체실, 예약 조회·취소·반납, 한 공간 자리)는 도구가 없어 모두 `tools.required`와 `cards`에서 떨어졌습니다. 대부분 거절 문구로 답해 행동도 CHAT으로 읽혔습니다.
- **ASK 15케이스**(공간 후보, 빠진 시각·시간, 같은 이름의 친구, 공강 슬롯)는 대부분 되묻지 않고 거절해 행동과 문구에서 떨어졌습니다. 공간 후보나 빈 슬롯을 물으려 해도 알 도구가 없습니다.
- **거절 15케이스**는 카드 없음은 모두 맞았고 행동도 거의 REFUSE였지만 이유가 틀렸습니다. 본관·다른 층·다른 도서관에 "미구현", 온라인 예약이 없는 공간에 "현장"을 말해야 하는데, 모델은 공간 예약 전체를 지원하지 않는다고만 했습니다. 조건 거절(내일 좌석, 4일 뒤, 23:30부터 7시간)과 8명 제한 케이스는 `proposeLibraryBooking`을 거쳐야 해서 `tools.required`에서도 떨어졌습니다. `p6-group-rooms-nine-people`은 한 실행이 8명 제한 문구를 맞혔지만 도구 검사로 실패했습니다.
- **튜토리얼 8케이스**는 튜토리얼 도구가 없어 모두 `tools.required`에서 떨어졌습니다. `p6-tutorial-exhibition-today`는 `searchGlobalEvents`로 오늘의 전시(가을 소장품전)를 맞게 답했지만, 라벨이 요구하는 `getTutorial`이 없고 `only` 밖의 `showGlobalEvents`를 불렀습니다. `p6-tutorial-admin-shuttle`은 `getShuttle`을 불러 셔틀 위치가 없다며 승강장을 모른다고 답했습니다.
- `p6-common-free-time-not-library`는 라벨대로 `findFreeTimeEvents`를 불렀지만, `only`가 허락하지 않은 `getMyDay`를 함께 불러 세 실행 모두 떨어졌습니다.

실행별 검사는 결과 파일 `-2.md`의 성적표에 있습니다.

## 멈춘 run

P4(`--world p4 --budget 1`), P5(`--world p5 --budget 2`), large-world-v1(`--world large-world-v1 --budget 2`), P19 두 번째 실행(`--budget 4`)은 21:21:46에 같은 커밋에서 시작했다가, **PM이 비용을 아끼려고 실험을 줄이기로 해** 21:32:11에 프로세스를 멈췄습니다. 앞의 셋은 약 10분, P19 두 번째는 약 3.5분 돌았고, P19 세 번째는 시작하지 않았습니다. 하네스는 결과를 run이 끝날 때만 쓰므로 남은 파일이 없습니다. 쓴 비용은 기록되지 않았고, 같은 세계의 이전 run 속도로 어림하면 약 USD 1.5–2.2입니다. 그래서 티켓의 "P4와 P5를 보고로 한 번" 항목은 이 기록에 없습니다.
