# Fix the timetable OCR parser (P13 follow-up)

Branch `2.0/fix-timetable-ocr`, from `2.0/Main` at `be10903`. Code: `mobile/src/features/timetable-ocr/`. This page is
the plan, written after reading the pipeline end to end and before any code change. File:line references are to
`be10903`.

## What the user asked

1. Stop using ML Kit's confidence to decide what is kept. A class, a time, a room or a title word is kept or dropped
   for structural reasons only: where it is on the grid, the block's geometry, whether text is there. Android and iOS
   follow the same rules.
2. List how a typical timetable picture could fail, prove the failures with tests where feasible, then fix what can be
   fixed safely, test first.
3. Dark mode fails today (the user's own screenshot). Add it as a test case.
4. No rules tuned to particular screenshots. Measure the background, the grid and the blocks from the image itself;
   keep a constant only when it has a reason that does not come from the four reference screenshots.

## Review decisions (함재현 on PR #113, 2026-10-22)

These override the plan below where they differ.

1. **Confidence.** Dropped for classes and titles as planned (`NAME_CONFIDENCE`, the title's 0.3 filter, the
   two-character rule). **Kept for linking a room to a building**, as a low floor: `ROOM_CONFIDENCE` 0.5 on Android,
   since a misread digit can land on another real building (301 → 307) and the spec's story 11 is "never sent to the
   wrong place", while an unlinked room is harmless. The four reference screenshots' rooms read 0.82–0.95, so 0.5
   refuses none of them. On iOS (no confidence) the room must be read inside one whole OCR element, for rooms only.
   `meanConfidence` and a line's confidence stay only for this.
2. **Dark-mode fixture.** The real screenshot and its ML Kit output are not available yet (no image file, no device
   run). The synthetic case stays; the screenshots test lists `dark-1` as to do and runs it, held to the same hard bars,
   once its output and ground truth are saved (`PENDING_SCREENSHOTS` in `__tests__/support/timetable-ocr.ts`).
3. **Out of scope:** photos of a screen (#22), a professor's name inside the block (#26), half-width overlapping
   classes (#20). Stated here and in `accuracy.md`.
4. **The P13 spec** (`.scratch/iteration-2/P13-timetable-ocr/spec.md`) is updated to match decision 1.
5. **`…` joining (#6).** A name printed cut with `…` joins a whole name only when exactly one whole name in the
   timetable starts with it; otherwise it stays a class of its own (`물리…` beside 물리학 and 물리학실험 stays apart).
6. **Start-uncertain (#10).** The day header's band, measured on the header row, counts as plain above a block, so a
   block at the first hour right under a shaded header is not dropped.
7. **Reference screenshots.** "No building linked wrongly" stays a hard bar beside at least 48 of 50 times; the room-link
   numbers with the 0.5 floor are reported in `accuracy.md`.

## General mechanisms replacing screenshot-tuned rules

- **Background colour**, measured: the most common colour (quantised) inside the grid's area. Replaces "white" and
  "value ≥ 200".
- **Grid colour and contrast**, measured: unsaturated pixels that differ from the background but by less than text
  does. Replaces "value 170–250".
- **Block pixel** = chroma above the background's chroma by a margin. Replaces saturation ≥ 0.25 and value ≥ 80. The
  margin is a fraction of the RGB range: grey UI and its anti-aliasing stay well under it in any theme.
- **Separator inside a block** = a row leaning towards the measured background. Replaces "lighter than the block".
- **Plain row** next to a block = close to the background (or the grid). Replaces "near white".

Constants that stay, with why they are general: the 5-minute rounding (the apps' grid), a quarter cell as the
smallest block (15 min, the shortest slot any timetable app draws), the RANSAC tolerance of a fifth of an hour, the
morphological close radius (the small copy is always about 330 px wide, so it scales with the picture), `FADE_DISTANCE`
(flat UI draws a block in one colour; a drift is a gradient). Rules that stay tuned to the reference apps are listed in
the final report.

## Test plan

Test first: each fix starts with a failing test.

- The synthetic generator (`__tests__/support/timetable-ocr-synthetic.ts`) gets a theme (background and grid colour),
  glyph strokes inside blocks (white text to close), a `scale` for the OCR boxes, and a height.
- **Dark mode**: the user's timetable drawn as described (1179 px wide, #1c1c1e background, #2c2c2e grid, 9–20 labels,
  the eleven blocks with their names and rooms, the last block running off the bottom with a gradient). Expected: every
  block but the cut one read, with the right times, names and rooms; the multi-room block linked to `61`; `스튜디오…`
  joined to its whole name.
- One test per fixed mode above (#2–#11), each red before its fix.
- Confidence: a test that the same OCR output with confidences 0.1 and with null reads the same classes; the old
  `low-confidence` / `too-little-text` test is replaced.
- The four reference screenshots: at least 48 of 50 times, nothing read that is not there, no building linked wrongly,
  the same with and without confidence. The new number is reported.
- Whole mobile suite, typecheck and lint at the end.
