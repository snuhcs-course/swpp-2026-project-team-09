# 공식 행사·비교과·생협 식단 직접 연동 준비

조사일: 2026-09-27 KST. 관측 시각: 02:03~02:05 KST. 사용자 요구는 **첫 프로토타입부터 실제 원천 데이터 사용**이며, SNUTT·행샤의 운영 앱/API를 데이터 공급자로 사용하지 않는다. 이전 행샤 연동 보고서의 운영 API 추천을 이번 작업에 적용하지 않는다.

공식 사이트의 공개 목록 3개를 각 1회 직접 GET하고, 비교과 상세 중간 경로 1회와 날짜를 명시한 식단 경로 1회를 추가 확인했다. 공식 행사 상세 1건은 웹 조회 도구로 읽었다. 공개 저장소는 기존 조사 사본의 접근 방식을 참고했으며 코드를 실행하거나 복사하지 않았다. 로그인·폼 제출·신청·예약·반복 수집·문의 전송은 하지 않았다. 아래는 구현 전 확인 결과이며 수집기 구현이나 지속 운영 검증은 아니다.

## 결론

**서울대학교 공식 행사 게시판과 생협 식단은 공개 HTML만으로 실제 데이터를 읽는 첫 구현을 시작할 수 있다. 비교과는 공개 목록을 읽을 수 있지만 상세 본문 접근과 필수 필드 완성은 추가 확인이 필요하다.** 세 원천에서 외부 앱용 공식 JSON API·이용 한도·재배포 계약을 확인한 것은 아니다. HTML 공개 조회 성공과 정기 수집·이미지 저장·재배포 조건은 구분한다.

| 원천 | 직접 관측 | 인증 경계 | 첫 프로토타입에 가능한 범위 |
|---|---|---|---|
| [서울대학교 공식 행사 목록](https://www.snu.ac.kr/snunow/events) | HTTP 200, `text/html; charset=UTF-8`, 2026-09-27 02:03:44 KST | 로그인·Cookie 없이 목록 수신. 공식 상세 1건도 웹에서 공개 열람 | 제목·원문 ID·게시된 날짜/기간·상세 본문의 장소/시각을 파싱해 실제 행사 카드 생성 |
| [비교과 목록](https://extra.snu.ac.kr/ptfol/pgm/index.do) | HTTP 200, `text/html;charset=utf-8`, 02:03:45 KST | 목록은 무인증 수신. 상세 GET은 JS 전환용 중간 HTML이며 최종 상세 인증 여부 미확정 | 원문 ID·제목·기관·유형·신청/활동 기간·대상·운영 방식. 활동 시각/장소가 없는 항목은 추천에 임의 보충하지 않음 |

웹 조회 도구의 캐시와 직접 GET은 신선도가 달랐다. 비교과의 웹 캐시는 9월 중순 목록이었지만 직접 GET에는 9월 26일 신청 시작 항목이 있었다. 식단 웹 캐시와 당일 직접 GET도 식당 행이 달랐다. **앱 수집기는 원천 응답의 날짜와 직접 관측시각을 사용하고 검색 캐시를 운영 데이터로 사용하지 않는다.**

## 서울대학교 공식 행사 게시판

### 확인된 읽기 경로와 데이터

- 목록: `GET https://www.snu.ac.kr/snunow/events`.
- 페이지 이동: 목록의 실제 페이지 링크를 따라 `page` 쿼리를 사용한다. 이번 조사에서는 다음 페이지를 수집하지 않았다.
- 상세: 목록 링크의 `GET /snunow/events?md=v&bbsidx={게시물ID}`. `bbsidx`는 source key로 사용할 수 있다.
- 검색 form은 GET 방식이며 날짜 입력 이름은 `df`, `dt`, 검색어는 `q`다. 날짜 필터가 포함된 요청은 이번 조사에서 실행하지 않았다.
- 응답은 서버 렌더링 HTML이다. 목록에서 현재 시점의 미래 일정(9월 말~10월)을 읽었다. JSON API는 확인하지 않았다. [공식 목록·검색 화면](https://www.snu.ac.kr/snunow/events)

상세 관측 예시인 [콜로퀴움 공지](https://www.snu.ac.kr/snunow/events?bbsidx=176102&md=v)에는 **2026-09-28 13:00**, **아시아연구소 101동 220호**가 본문 텍스트로 제공된다. 종료 시각·지도 좌표는 이 예시에서 확인되지 않는다. 목록에 붙은 날짜는 행사·신청·모집 기간일 수 있으므로 카드 날짜를 항상 실제 활동 시각으로 확정해서는 안 된다.

### 구현 준비 제안

1. `SnuOfficialEventProvider`가 HTML을 가져오고 Cheerio 같은 정적 DOM 파서로 읽는다. 목록 selector 후보는 `.board-imgline a.item[href*="bbsidx"]`; 상세는 `.board-view .header .title`, `.board-view .content`이며 페이지 변경을 감지할 계약 검증이 필요하다. 이 접근 방식은 기존 공개 코드에서도 사용하지만 해당 코드를 복사하지 않고 직접 관측 HTML에 맞춰 작성한다. [기존 조사에서 참고한 목록·상세 파싱 방식](https://github.com/wafflestudio/hangsha-server/blob/4a33bf96bff8b71f1fb837c779da057e136f7784/hangsha/batch/src/main/kotlin/com/team1/hangsha/batch/crawler/SnuNowCrawler.kt#L111-L143)
2. 외부 키는 `snu_official_events + bbsidx`; `sourceUrl`, `title`, `rawDateLabel`, `descriptionText`, `fetchedAt`, `contentHash`를 저장한다. 실제 활동 구간·신청 구간·장소는 별도 필드로 둔다.
3. 날짜와 장소는 규칙 기반 추출을 먼저 적용하고, 불명확한 본문에만 AI 추출을 적용한다. 추출값에는 근거 문장과 검토 상태를 남긴다. 종료시간이 없으면 임의의 기본 시간을 공식 값으로 저장하지 않는다.
4. 건물 번호/이름을 자체 캠퍼스 장소 사전에 연결한다. 실제 장소가 확인되지 않은 행사는 목록에는 남겨도 지도에 임의 마커를 찍거나 이동시간 기반 추천 대상으로 삼지 않는다.
5. 첫 실데이터 연결 확인은 목록 1페이지와 연결된 상세 소수로 충분하다. 이후 주기는 게시물 변화율·원천 이용 조건을 확인하고 정한다. 정정 확인을 위해 기존 게시물의 본문 hash도 재확인할 수 있게 설계한다.

## 서울대학교 비교과관리시스템

### 목록과 상세의 경계

공개 [목록 경로](https://extra.snu.ac.kr/ptfol/pgm/index.do)는 현재 HTML 카드에 프로그램 ID, 제목, 주관 기관, 유형, 대상, 온라인/오프라인 여부, 신청 기간, 활동 기간, 일부 정원/신청 수를 제공한다. form의 페이지 필드는 `currentPageNo`다. 날짜 조건 UI는 있으나 정확한 기간 요청 계약은 이번 조사에서 검증하지 않았다.

직접 받은 최신 첫 항목은 의료 인공지능 세미나 18회차로, 신청 기간은 2026-09-26~09-30이지만 활동 기간은 `-`였다. **실제 목록이어도 데이터 완전성은 별개**다. 이 항목의 활동 시간을 만들어 넣으면 안 된다.

HTML의 실제 연결 ID를 이용한 `GET /ptfol/pgm/view.do?dataSeq=PGM012002249`는 02:04:52 KST에 HTTP 200을 반환했다. 그러나 응답은 행사 본문이 아니라 다른 상세 경로로 form을 전송하는 JS를 포함한 중간 페이지였다. 사이트 공통 코드에는 대기 제어 흐름도 있다. 이번 조사는 그 JS를 실행하거나 form을 제출하지 않았다. **HTTP 200을 최종 상세 공개·수집 성공으로 기록하지 않는다.** [관측한 공개 상세 진입 URL](https://extra.snu.ac.kr/ptfol/pgm/view.do?dataSeq=PGM012002249)

페이지에 로그인 메뉴가 있다는 이유만으로 모든 읽기에 로그인이 필요하다고 단정하지 않는다. 반대로 공개 목록이 있다는 이유로 개인 활동·신청·최종 상세까지 공개라고 추정하지 않는다. 최종 상세의 정상 브라우저 진입에서 인증이 요구되는지는 별도 확인 대상이다.

### 구현 준비 제안

- `SnuExtraProgramProvider`의 1차 계약은 **공개 목록 읽기**로 둔다. 목록 카드의 `global.write`에 들어 있는 ID를 파싱하고, 그 문자열/스크립트를 실행하지 않는다.
- 신청 기간·활동 기간·활동 시각은 분리한다. 실제 장소가 없는 경우 `location=null`, `detailState='unverified'`로 저장한다.
- 실제 시연에 필요한 행사는 공식 게시판에서 날짜·장소가 확인되는 항목을 먼저 사용한다. 비교과 데이터가 빠졌다고 생성한 샘플로 채우지 않는다.
- 비교과 상세가 반드시 필요하면 정상 공개 브라우저 경로와 제공자의 읽기 조건을 먼저 확인한다. 로그인 벽·접근 제한이 나오면 해당 기능을 인증 의존 항목으로 기록한다. 학교 ID/비밀번호를 자체 서버에서 수집하는 방식은 이번 계획에 포함하지 않는다.
- 서로 다른 원천의 동일 행사는 원문 링크·주관 기관·시각을 통해 중복 후보로 묶되, 회차가 다르면 별도 행사로 유지한다.

## 서울대학교 생활협동조합 식단

### 확인된 당일 조회

`GET https://snuco.snu.ac.kr/foodmenu/?date=2026-09-27`을 02:04:52 KST에 직접 조회했다. HTTP 200 HTML 응답의 `input[name="date"]`가 `2026-09-27`과 일치했다. 기본 경로의 form도 `date` 이름의 날짜 필드를 사용한다. 따라서 서버가 날짜를 지정해 실제 식단을 조회하는 경로가 확인되었다. [날짜를 지정한 공식 식단](https://snuco.snu.ac.kr/foodmenu/?date=2026-09-27)

식단 본문은 `table.menu-table`이며 행마다 식당명(`td.title`), 아침(`td.breakfast`), 점심(`td.lunch`), 저녁(`td.dinner`)을 제공한다. 당일 직접 응답에는 기숙사식당의 연휴 휴무가 표시되었다. 페이지는 가격이 섞인 긴 메뉴 텍스트와 줄바꿈을 포함하며 모든 끼니가 동일 형식의 메뉴 배열인 것은 아니다. [공식 식단 페이지](https://snuco.snu.ac.kr/foodmenu/)

메뉴표 자체에 모든 식당의 정규화된 건물 ID·위도/경도가 들어 있다는 근거는 확인하지 못했다. 식당명은 자체 장소 사전과 연결하고 공식 식당안내/지도 정보를 별도로 검증한다. 빈 칸은 휴무와 동일하게 처리하지 않는다. 오늘 원천이 실제 휴무를 반환했다면 휴무를 보여 주는 것이 실제 연동 성공이다.

### 구현 준비 제안

- `SnuCoopMenuProvider.getMenus(date)`는 날짜를 `Asia/Seoul` 기준 `YYYY-MM-DD`로 보내고, 응답 날짜가 요청 날짜와 같은지 먼저 검사한다.
- `source='snu_coop'`, `restaurantKey`, `serviceDate`, `meal`, `rawText`, `items`, `availabilityState`, `fetchedAt`, `sourceUrl`로 정규화한다. 메뉴/가격 추출은 `rawText`를 보존하면서 점진적으로 한다.
- 상태는 최소 `available`, `closed`, `not_published`, `unavailable`로 구분한다. 명시적인 휴무만 `closed`; timeout/HTML 구조 변경은 `unavailable`; 공란은 근거 없이 휴무로 해석하지 않는다.
- 원천은 로그인·브라우저 실행 없이 HTML을 내려 주므로 초기에는 NestJS HTTP + DOM 파서면 충분하다. WordPress 내부 API나 생협의 비공개 endpoint를 추측해 호출할 필요가 없다.
- 동기화 실패 시 마지막 실제 데이터를 날짜·확인시각과 함께 보이거나 수신 실패 상태를 표시한다. 다른 날의 메뉴를 오늘 메뉴로 바꾸거나 샘플을 투입하지 않는다.

## 공통 준비 사항과 미확인 조건

**기술적으로 필요한 최소 구성:** NestJS 안의 제공자별 HTTP/HTML 파서, PostgreSQL의 실제 관측값 저장, 수집 작업 실행기, 관리자용 재수집/실패 확인 화면이다. 처음에는 수동 트리거한 단발 수집으로 연결을 검증하고 주기 실행은 후속으로 추가할 수 있다. 서버를 여러 대로 나눌 필요는 없다.

다음은 아직 확인되지 않았다.

- 정기 자동 조회, 호출량, 장기 보관, 재표시, 이미지 복제, AI 입력에 관한 제공자의 명시적 이용 조건.
- 문서화된 외부 JSON API·변경/삭제 피드·지원 SLA의 존재 여부. 이번에 확인한 경로가 HTML이라는 뜻이지 API가 절대 없다는 뜻은 아니다.
- 비교과 최종 상세의 공개 접근 여부와 상세 시각/장소 필드 품질.
- 각 게시판의 전체 행사 포괄성, 모든 학과 공지 수집, 시간·장소 정정의 반영 지연.

운영 전 원천 담당자와 조회·표시 범위를 확인하고, 수집기에 동시성 제한·timeout·재시도 상한·변경 감지·중단 스위치를 둔다. 공식 게시판은 저작권 표기를 하고 있으며 공개 페이지의 존재가 포스터 재호스팅 등 모든 이용을 포괄한다고 보지 않는다. 문의는 보내지 않았다. [공식 행사 게시판 하단 표기](https://www.snu.ac.kr/snunow/events)

**첫 프로토타입의 완료 판정 제안:** 공식 원천의 실제 행사 카드와 당일 식단/휴무를 앱에서 표시하고, 모든 항목에 원문·조회시각을 연결한다. 누락된 날짜·장소, 수집 실패, 휴무를 각각 표시하며 데이터를 만들어 보충하지 않는다. 이번 문서는 그 구현 경로를 확인한 것이며 프로토타입을 구현·검증한 결과는 아니다.
