# 서울대학교 앱의 정류장 기준 셔틀 정보 조사

조사일: 2026-09-27, 주요 조회 시각 04:09–04:11 KST. 공개 학교 공지, 운행사 링크, 공개 HTML/JavaScript와 그 화면이 사용하는 읽기 요청을 확인했다. 로그인, 앱 설치·역분석, 인증정보 전송, 임의 노선 ID 탐색, 반복 polling, 외부 연락은 하지 않았다.

## 결론

**기존 `shuttlebus.snu.ac.kr` 외에, 학교 공지가 연결한 현재 접근 가능한 셔틀 노선도·차량 표시 경로를 찾았다.** 실제 제공 화면은 위경도 지도 대신 정류장이 배치된 노선도에서 버스 아이콘을 표시한다. 사용자가 설명한 정보 형태와 부합한다. 다만 서울대학교 네이티브 앱의 실제 네트워크를 관찰한 것은 아니므로 앱이 현재 정확히 이 주소를 호출한다고 확정하지 않는다.

새 경로의 Google Sites와 `web.busin.co.kr`는 정상 TLS로 HTTP 200을 반환했다. 순환셔틀 읽기 호출도 성공했다. 일요일 새벽에는 차량 문자열이 비어 있었고 공개 화면은 운행 0대·주말 미운행을 표시했다. 따라서 **연동 경로가 없다는 판단은 수정해야 하지만, 운행 중 차량 정보까지 실측 완료한 상태는 아니다.**

## 공개 읽기 계약과 단발 관측

순환셔틀 화면의 공개 JavaScript가 다음 조회를 호출한다.

```text
POST https://web.busin.co.kr/BuslineCircleS.aspx/GetRoute
Content-Type: application/json; charset=utf-8

{"data":",F,41946,snu_1"}
```

2026-09-27 04:10:54 KST에 동일 요청을 한 번 보냈고, 정상 TLS에서 HTTP 200 및 `application/json; charset=utf-8` 응답을 받았다.

```json
{"d":""}
```

화면의 JavaScript는 `response.d`를 `;`로 나눈 뒤 각 행을 `/`로 나누어 아래 필드를 읽는다. 빈 응답이었으므로 실제 차량 행의 값과 안정성은 아직 확인하지 못했다.

| 순서 | 클라이언트 변수 | 확인한 용도와 한계 |
| --- | --- | --- |
| 0 | `carid` | 버스 아이콘 DOM 식별자 구성. 영구 vehicle ID인지 미확인 |
| 1–2 | `busx`, `busy` | 아이콘을 `translate(...px,...px)`로 배치하는 **노선도 픽셀 좌표**. 위경도가 아님 |
| 3 | `carcnt` | 1보다 크면 아이콘에 개수 배지 표시 |
| 4 | `carnos` | 아이콘 클릭 시 표시하는 차량 정보 문자열 |
| 5 | `carcode` | 읽지만 해당 공개 화면에서 활용하는 의미는 확인하지 못함 |

노선 HTML은 정류장 이름과 노선도 안의 고정 배치 좌표를 별도로 제공한다. 예를 들어 순환 노선에는 정문·법과대·자연대·농생대·38동·302동·301동·기숙사삼거리 등이 배치된다. 개별 stop ID, 실제 위경도, 도착예정시간(ETA), 현재 정류장 도착/출발 이벤트가 이 응답에 제공된다고 가정하지 않는다.

화면은 `setInterval(..., 5000)`으로 재조회한다. 바로 옆 주석의 30초 표기와 코드가 다르므로 관측상 클라이언트 설정은 5초이다. 이것이 외부 앱에 허용된 호출 간격이나 실제 원천 데이터 갱신 주기를 보장하지는 않는다. 또한 아이콘 클릭의 시각 문자열은 **초기 HTML에 박힌 페이지 생성 시각**이며 GPS 관측 시각으로 사용할 수 없다.

## 연동 설계에 주는 의미

1. 첫 연동 대상은 정상 TLS로 접근 가능한 새 공개 노선 화면의 읽기 경로를 우선 검토한다. 이전 DWR의 만료 인증서 문제를 새 경로에도 적용해 기능을 포기하지 않는다.
2. worker가 노선별 조회를 모아 Redis에 최신 snapshot을 저장하고, 변경 시에만 socket-server가 구독 단말에 알린다. 단말마다 제공자에 직접 polling하지 않는다.
3. 이 데이터만 확보된다면 우리 UI도 **정류장 노선도 기반 위치**로 제공한다. 픽셀 좌표를 위경도로 바꾸어 실제 지도 위 정밀 차량 위치인 것처럼 표시하지 않는다. 지리 지도 위 표현은 지리 데이터와 매핑 의미가 검증될 때 별도로 설계한다.
4. stop 또는 segment로 정규화하려면 실제 운행 응답에서 도형상의 위치와 정류장 구간 관계를 확인해야 한다. 확인 전에는 원본 노선도 위치를 보존하며 `at_stop`·`departed` 같은 정확한 상태를 추론해서 확정하지 않는다.
5. `receivedAt`은 우리 서버 조회 시각이다. 원천 `observedAt`이 없으면 별도로 미제공 처리한다. 빈 응답·공식 미운행 안내·통신 오류·오래된 응답을 구분한다. 예시 차량으로 채우지 않는다.

공개 읽기 경로는 발견했지만 외부 개발자용으로 보장된 API 문서, 사용·캐시·재배포 조건과 허용 주기, 장기 지원 여부는 확인하지 못했다. 실제 운영 시간의 소수 응답에서 차량 행·정류장 간 이동을 검증하면 어댑터 구현 가능성과 데이터 품질을 구체적으로 판단할 수 있다. 이 조사는 셔틀을 후속 기능으로 미루겠다는 사용자 결정이 아니다.

## TLS 및 보존 메모

- `서울대.info`의 ASCII 도메인은 `xn--vk1bo1ydle.info`다. 최초 일반 HTTPS 요청은 인증서 이름 불일치로 실패했다. 인증정보 없이 HTML의 이동 목적지만 한 번 읽기 위해 조사용 검증 예외를 사용했다. 앱이나 서버의 TLS 검증을 해제하는 방식은 채택하지 않는다.
- 이동 목적지인 Google Sites와 실제 `web.busin.co.kr` 노선 화면·읽기 요청은 일반 인증서 검증으로 성공했다. 운영 연동에서 안내용 도메인의 TLS 예외를 거칠 이유가 없다.
- 조사 사본은 `/private/tmp/snu-new-shuttle-*.html`, `/private/tmp/snu-new-shuttle-live-41946.json`이다. 임시 사본이므로 장기 보존을 보장하지 않는다.
