## Question

확정한 범위와 구조가 실제로 구현 가능한지 어떤 검증을 먼저 수행하고, 무엇을 충족하면 MVP를 완료로 볼 것인가? 두 Android 기기의 지도·백그라운드 위치·배터리·권한 철회, 해당 범위의 QR 중복, AI 도구 정확성/지연, 재연결과 실패 복구를 포함한다. 개발 기간·테스트 참여자·예산이 확인되면 실행 계획에 넘길 검증 순서를 정하되 이 지도에서 제품 구현은 하지 않는다.

## Comments

- 2026-09-27 성능 기여 방향: 같은 입력·자원·도착률에서 태그/DB 기준, 임베딩 추가, 동일 알고리즘+Redis, 선택적 reranker를 각각 비교한다. DB/Redis/AI의 총비용·p95·cold/warm/장애·조건 위반·적합도와 만족도를 기록하며 측정 전 개선율을 주장하지 않는다. 자동 가입 완료는 선호의 긍정 라벨이나 수락률로 쓰지 않는다. [매칭 평가 설계](15-party-matching.md)

- 2026-09-27: 현재 실기기 한 대, 이후 두 대 사용 가능. 우선 실기기+Google 로그인 가능한 에뮬레이터의 독립 계정으로 소켓 동기화를 검증하되 두 실기기 GPS·백그라운드·배터리 검증은 별도로 남긴다. 첫 실행 목표 2026-09-28은 아직 완료 약속이 아니다.
- 샘플 데이터는 첫 프로토타입에서 사용하지 않는다. 조회 실패·실제 휴무·운행 데이터 부재를 구분한다. 관정 기능은 사용자 허용으로 초기 보류했으며 셔틀 실제 차량 미검증은 완료로 세지 않는다.
