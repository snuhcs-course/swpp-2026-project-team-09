## Question

사용자가 행사 참여, 친구 약속, 생활 편의 세 흐름 모두 MVP 필수로 선택했다. 각 흐름의 최소 완료 조건과 실제 연동 수준은 무엇인가? 시간표 입력·이미지 추출, QR 보상, 개인 행사, 채팅 자동완성의 포함 여부를 정한다. 제안서 내용과 사용자의 최종 범위 결정을 구분한다.

## Comments

- 2026-09-27 사용자는 최초 MVP를 프로토타입으로 확인하기 위한 준비 사항을 요청했다. React Native 실기기에서 지도·실제 위치·소켓·Google 로그인을 연결하고, 외부 행사·식단·좌석·셔틀은 표시된 샘플로 시작하는 안을 권고 후보로 제시했다. 외부 샘플 허용 여부와 기한·기기 수는 질문 중이며 답변 전까지 확정하지 않는다.
- 공동 퀘스트의 기본 의미는 참여자가 함께 보는 확정 활동 계획과 변경 동기화다. 앞선 설명에 등장한 도착 체크·단계별 진행률·전원 완료 규칙은 추가 제안이므로 초기 필수 기능으로 자동 포함하지 않는다.

- 2026-09-26 후속 요청에 따라 [제안서 전체 기능의 기술 설계 초안](../spec.md)을 작성했다. 세 흐름의 모든 제안 기능과 부가·확장 기능을 검토할 수 있으며, 기능별 채택 수준은 아직 사용자와 합의하지 않았으므로 티켓은 열어 둔다.

- 2026-09-26 사용자 답변: “생활 편의까지 세 흐름 모두 필수.” 큰 범위는 확정되었지만 세부 깊이와 완료 조건은 아직 미정이므로 티켓은 열어 둔다.

- 2026-09-27 추가 답변으로 앞선 샘플 제안은 기각되었다. 첫 프로토타입부터 외부 서비스·데이터를 실제로 연결하며 SNUTT·행샤는 코드만 참고한다. API를 확보하지 못한 관정 기능은 사용자 허용에 따라 후속 MVP에 보류한다. 전체 강좌 검색, QR, 자동완성 등의 첫 구현 깊이는 이 답변만으로 확정하지 않는다.
- 첫 실행 희망일은 현재 날짜 기준 2026-09-28이며 Android 두 대 중 현재 한 대를 이용할 수 있다. [계정·개발 환경 준비](12-prototype-readiness.md)의 선행 조건과 실제 연동 한계를 숨기지 않는다.
