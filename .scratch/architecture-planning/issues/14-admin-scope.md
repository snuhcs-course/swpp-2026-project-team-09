## 현재 사용자 결정

Next.js admin-frontend를 루트에 둔다. 최신 답변에 따라 관리 업무 API는 main-server 코드에 통합하고 같은 서버 이미지의 **어드민 전용 파드/실행 pool**을 띄운다. 직전 별도 admin-backend 및 공식 행사 소유권 분리 질문의 추천안은 채택하지 않는다.

2026-09-27 착수 전 답변: 초기 어드민은 **팀원 전용**으로 시작한다. 행사 생성·수정·발행·취소와 연동·매칭 상태 확인부터 제공하는 추천안을 작업 기준으로 둔다. 외부 주최자 가입·조직별 위임은 초기 범위에 넣지 않는다. 실제 관리자 계정 목록/역할 부여와 개발용 초기화 도구는 별도 확인 대상이다.

## 코드·배포·데이터 경계

main-server의 일반 API controller와 관리자 controller는 같은 행사 application service·repository·소유 DB를 사용한다. 관리자 접근 권한은 별도로 검사한다. 관리용 요청은 main-admin 실행 그룹으로, 일반 요청은 main-public으로 라우팅하는 안이다. Kubernetes는 필수가 아니며 컨테이너/관리형 서비스로도 분리할 수 있다. 같은 이미지를 role 설정에 따라 실행하며 main-public에 관리 controller를 등록하지 않는 구성을 제안한다. [상세 저장소·실행 설계](13-project-organization.md)

admin-frontend의 요청을 main-public으로 다시 넘기는 프록시 구조가 아니다. 실제 행사 조회·수정·발행 처리는 main-admin 파드에서 수행한다. main과 admin 사이에 공식 행사 복제 이벤트를 새로 만들 필요가 없으며, 저장/outbox→브로커→socket→앱 재조회 흐름은 유지한다. DB를 공유하므로 관리 쿼리의 DB 부하는 여전히 일반 요청에 영향을 줄 수 있다.

관리 보고서·대량 내보내기·수집 재실행은 worker에 작업을 요청하고 상태/결과를 조회하는 안이다. 관리자 pool의 DB connection 상한·요청 제한과 worker 작업별 concurrency를 검토한다. replica 수를 늘려 DB 연결이 무제한 증가하지 않게 한다. 성능 격리가 완료되었다고 주장하려면 부하 시험이 필요하며 아직 수행하지 않았다.

## 미확정 기능과 정책

- 팀원 중 실제 관리자 계정 목록/권한 부여 방식. 외부 주최자 접근은 초기 범위에서 제외한다.
- 첫 행사 작성·수정·발행·취소, 연동 상태 확인, 개발용 테스트 초기화 범위.
- Next 웹 세션/로그인 방식과 관리자 자격 부여. 학교 도메인만으로 관리자 권한을 주지 않는다.
- 개발 전용 테스트 계정/데이터 격리. 실제 외부 데이터를 가짜 행사·식단·셔틀로 대체하지 않는 원칙 유지.
- 관리 요청의 로그·감사 기록 및 통계에 포함할 데이터. 관리자 역할만으로 개인 위치·시간표·대화를 전부 열람하는 설계는 아니다.

## 근거와 상태

[어드민 프레임워크 조사](../research/admin-framework.md)의 Next.js 선택 사실과 [어드민 실행 경계 조사](../research/admin-service-boundary.md)의 최신 파드 분리 절을 참고한다. 이전 독립 admin DB·projection 설계는 검토 이력이며 현재 선택이 아니다. 파일·파드·클러스터를 생성하거나 배포하지 않았다.
