# 07: Assistant library and tutorial tools

Blocked by: 01, 02, 06 (06 for merge order only; 01 and 02 for what the tools read)

## What to build

The Assistant understands 관정도서관 requests and tutorial questions. "7층 열람실 5시부터 두 시간 잡아줘" gets a booking card, "지금 8층 자리 있어?" a seats card, "반납해줘" a return card, "내 예약 보여줘" a myBookings card. A space named several ways is resolved from the catalogue, an ambiguous one is asked about, and requests outside the window, the hours, the capacity, the online spaces or the scope are refused with the reason. "학생증 어디서 받아?" is answered from the tutorial's text only. The server decides; the model passes ids and the User's words, and never sees seats, bookings, 학번, registered names or the session. Cards carry no live data and book nothing; the phone does that (ticket 08).

**Merge order.** This ticket can be built now in parallel, but its chat changes land only after ticket 06 is merged with its C0 tag, R0 and the P19 baseline, and it is rebased onto that. It also reads `affiliation` (ticket 01) for `notEligible` and the tutorial content and progress (ticket 02) for `getTutorial`. These two edges are added to the suggested ones because the tools cannot run without those columns and that module; both are wave-1 tickets, so this ticket can be written against them in parallel and rebased.

The `library` card DTO, its `key` grammar and `clientCapabilities` are fixed in the spec, so ticket 08 builds against them with mocks now.

## Comments

- **Built on `3.0/P06-07-assistant-tools`** from `origin/3.0/Main` (ticket 02 merged, 01 and 06 not yet). Server only.
- **The catalogue** moved to `src/assistant/library/kwanjeong-spaces.yaml` (prettier reformatted it). `common` gained `booking_ahead_days`, `step_minutes` and `notes` (the card's Korean rules); seat sectors `mapImage`; 대학원 열람실 `for_affiliation: graduate`. Its strings (capacity "7–10", hours, durations) are read by their first range. "Every roomNo unique" is checked as: a roomNo on one floor and every sectorNo under its roomNo, since the sectors of one room share it; ids, sectorNos and seatNos are unique.
- **The card DTO** (for ticket 08): `{ kind: 'library', library: { key, action, space, date, start, minutes, seat, useDesc, useDescOptions, pledge, companions, questId, notes, until, target } }`, nested like the other cards, every field present and null when it does not apply. `until` (the end of a myBookings period) is the one field beyond the spec. Key grammar in `library-card.ts`: `book:<id>:<date>:<HHMM>:<min>[:s=<seat>][:e=<equipment>]`, `seats:<id>:<date>[:<HHMM>:<min>]`, `cancel:<id|->:<date|->:<HHMM|->`, `return:<id|->`, `myBookings:<from>:<to>`.
- **Gating.** Without `clientCapabilities: ['library']`, or with `LIBRARY_BOOKING_ENABLED=false`, all seven library tools answer `none` (the flag off adds the official link); `getTutorial` stays. Off, `GET /tutorial` serves the 관정 quest as a button quest with the official site's link. The room request endpoints do not exist yet (ticket 09), so their 404 under the flag is 09's.
- **Rulings from the PM (2026-11-02), built into `LIBRARY_RULES` and `TUTORIAL_RULES`:** several fitting spaces are asked about by name with no tool call (bare "7층 열람실/자리", "스튜디오", "모니터 있는 스터디룸"; headcount never narrows; "지금 7층 자리 있어?" is an ASK); refusals by the catalogue or the window, and a missing time, call no tool, so `findLibrarySpace`'s catalogue summary now carries each space's status; "아무 자리(나)" with no space is 7F-7A-zone2; "반납했어?" gets no card; times in questions as HH:MM; tutorial and facility questions go getTutorial → the app's other data (Global Events, Places) → the official link, and a fact found nowhere is "확인되지 않아요". The server still checks every condition.
- **대학원 열람실.** The rules say it is for graduate students without a tool call, since the model never sees 소속; the server answers `notEligible` unless `affiliation` is `graduate`. `affiliation` is read through ticket 02's `affiliationOf`, which tolerates its absence, so until ticket 01 merges every User gets `notEligible`.
- **보건진료소 facts.** `tutorial.yaml`'s health-clinic quest now says 3–4층 (진료 3층, 접수·수납 329호), floor 3, five health4u links, and `facts` (each with `source` and `checked: 2026-11-02`): hours, departments, how to use, cost, 대표전화. `facts` is a new optional field of the content; `getTutorial` returns it and `GET /tutorial` leaves it out. Saturday and vacation hours are not stated, so they are left out. The spec's row and body were fixed to match.
- **Privacy test.** `assistant-library-privacy` sets 학번, registered names and 소속 by SQL when ticket 01's columns exist, and otherwise still checks that no prompt, reply or log line holds them, a Class room, `affiliation`, BSEQNO or JSESSIONID.
- **Not changed:** `main-server/eval/` (ticket 06's; the normalisers belong there). No paid model run was made.
- **Test runs:** pnpm in the shell's PATH was an older one, so the integration tests ran with pnpm 12.6 shimmed first in PATH.
