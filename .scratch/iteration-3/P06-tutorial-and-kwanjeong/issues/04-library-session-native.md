# 04: Library session (native): login, the hidden web view, logout, library client and the fake library

Parent: [P06 spec](../spec.md) ("The library session (device only)")
Status: ready-for-agent
Blocked by: None (can start immediately)

## What to build

A User logs in to 관정도서관 once, in a full-screen web view showing the school's own login page, and SNU Now keeps the library session on the phone only, in the web view's own cookie jar, where app code never reads it. One library client in `mobile/src/library/` makes every library call from the phone through a hidden, same-origin web view, notices when the school's session has ended, asks the User to log in again and retries the pressed action once. 내 정보 has a "관정도서관 로그인" row with 로그아웃, and signing out of SNU Now logs out of the library too: logout really ends the session, at the library and in the web view's cookie jar, so the next person on the phone never sees the previous one's bookings. CI tests every library call through a fake transport backed by a fake library that serves the recorded responses and records each request, so no test ever reaches the real site.

**This is the only native change in P6.** It adds two native modules, `react-native-webview` and `@react-native-cookies/cookies` (used only to clear the web view's cookies at logout; app code still never reads a cookie), raises `version` in `app.json` from 1.0.0 to 1.0.1, and ships in one native Release by P03's flow (`infra/production/README.md` § The Production APK, `app-version.json`) together with P03 ticket 05's planned 1.0.1 verification release: one native build checks both.

Tickets 05, 08 and 09 build on the client's interface, the fake transport and the fake library, so these land in this ticket even before the native Release.

## Acceptance criteria

- [ ] **First, before anything else:** build Android and iOS once with `react-native-webview` and `@react-native-cookies/cookies` added (the iOS build by the Mac owner). The cookie module's last release, 6.2.1, is from 2022-05, and the app is RN 0.86 / Expo 57. If the cookie module does not build on either platform, stop and ask the owner for an alternative (for example a small local Expo module that calls `WKWebsiteDataStore` on iOS and `android.webkit.CookieManager` `removeAllCookies` on Android) before building the rest.
- [ ] `react-native-webview` and `@react-native-cookies/cookies` are the only modules added, and `version` is raised from 1.0.0 to 1.0.1 in `app.json` in the same change (CLAUDE.md § The app's native files). The app-fingerprint CI job reports the raised version. No other native file changes; the fingerprint comment stripping from #128 may ride along.
- [ ] The session lives only in the web view's cookie jar: no app code reads, copies or stores `JSESSIONID` (not SecureStore, not AsyncStorage, not a log). Both web views use the default persistent store (not `incognito`). The app keeps only the `kwanjeong.loggedIn` flag. The cookie module is used only to clear: lint rules forbid its `get`, `getAll` and `getFromResponse` (`no-restricted-properties`) and its import outside the one logout file in `mobile/src/library/` (`no-restricted-imports`), and a code review checks no cookie is read.
- [ ] Login: a visible web view loads `https://k-rsv.snu.ac.kr/NEW_SNU_BOOKING/pc/main`. When the URL is back on `k-rsv.snu.ac.kr` at `/pc/(main|booking|mybooking)`, the login is done: the app sets the flag and the view closes. No script is injected into any login page. After 5 minutes the view closes with "로그인하지 못했어요". Cancelling returns "no session" to the caller.
- [ ] The hidden web view: no size, kept mounted at the app's root while the flag is set, on `…/pc/main`. Every call, reads and writes, injects the one fixed script (`injectJavaScript`, its only argument made with `JSON.stringify`), which makes the form POST with `fetch` (`credentials: 'same-origin'`, `redirect: 'manual'`, `X-Requested-With: XMLHttpRequest`, `OS_KIND: WEB`, `referrer` `…/pc/booking/roomForm`) and posts back through `postMessage` only the parsed JSON or an error kind, as the spec's "The message protocol" fixes: `{ id, endpoint, body }` in, `{ id, ok, result | error }` out, unknown ids and other origins ignored, 20 s for the page load and 15 s per call, a timed-out write never retried by itself.
- [ ] The allow-list, held by the script and the client alike: the reads (`getSectorList`, `getRoomList`, `getSeatBookingList`, `getSeatInfoFromList`, `getUserCheck`, `getMyBookingList`), the room form read (only `tmpUserNames`, `tmpSchoolNos`, `.phoneNum`, `.eMail` posted back) and the writes (`setRoomBooking`, `setCancelBooking`), the writes accepted only from a card's confirmed action. Anything else, `setSeatReturn` included, gives `notAllowed`.
- [ ] HTTP 999, a redirect, a non-JSON reply or the hidden view landing off `k-rsv.snu.ac.kr`/`/pc/` gives `sessionEnded`: the client clears the flag and raises a "session ended" error the cards show as "관정도서관 로그인이 끝났어요. 다시 로그인해 주세요." with 로그인, which opens the login again; after the login the action is retried once.
- [ ] A helper builds the seat-map image URL `https://k-rsv.snu.ac.kr:444/MAP/WEB/area_<sectorNo>.png?version=20261022`, loaded with no cookie.
- [ ] One shared step in `mobile/src/library/`, "end the library session", does the logout, in order: when the `kwanjeong.loggedIn` flag is set, the hidden view loads the site's logout URL (15 s; a failure does not stop the rest), and when it is absent this step is skipped (no hidden view, no network call, no wait); every web-view cookie is cleared with `clearAll(true)` (then `flush()` on Android; on iOS only `true` clears `WKWebsiteDataStore`, where the web view's cookies are); and the flag is cleared.
- [ ] The 내 정보 row "관정도서관 로그인" shows 로그아웃 while the flag is set and calls that step.
- [ ] The app's `signOut()` (`mobile/src/auth/sign-in.ts`) calls that step before it forgets the main server's tokens, whether or not the flag is set.
- [ ] The forced end of the app's session, `endSession()` (`mobile/src/session/session-events.ts`), which forgets the tokens and shows the sign-in screen without going through `signOut()`, calls the same step before it forgets the tokens, whether or not the flag is set.
- [ ] The library client is an interface over a transport; the hidden-web-view transport is one implementation. The fake library: the redacted responses of `references/kwanjeong-fixtures` are copied to `mobile/__tests__/support/kwanjeong/`, and a fake transport serves them by endpoint and parameters and records every request (endpoint, form fields). It can be told to answer `sessionEnded`, `network`, `bookingFailInfo` or a taken seat.
- [ ] Privacy: the session, any library reply, phone, email and BSEQNO are never sent to our servers; the app's error reporting and logs drop library request and response bodies (checked in a test that fails a library call and inspects what reaches the reporter).
- [ ] Tests, named by ADR 0007:
  - unit: the fixed script run with a stubbed `fetch` and `postMessage` (the headers, the form encoding, the allow-list, 999, redirect and non-JSON giving `sessionEnded`, the room form parse); the client's id matching and timeouts;
  - integration: the client through the fake transport and the fake library for each read and write; session ended and the retry after login; logout calling the logout URL, `clearAll(true)` (and `flush()` on Android) and clearing the flag, from 내 정보, from `signOut()` and from `endSession()`; with the flag absent, no logout URL loaded and no hidden view, only the cookies cleared; the login screen's URL rule with the web view stubbed.
- [ ] **Person**, on one real Android phone against the real site after the native Release: one login, one seat booking made with the client and its return, and logout; after the 내 정보 logout the library asks for the password again; after an app sign-out and a sign-in with another account, the previous person's bookings are not visible and the library asks for a password; after a forced session end and a sign-in with another account, the previous person's bookings are not visible and the library asks for a password. The three logout checks are run on iOS too, with the Mac owner's iOS build. Recorded with screenshots in the PR. This is the spec's only hand check of the web views.
- [ ] The native Release is made by P03's flow, in one Release with P03 ticket 05's 1.0.1 verification: `version` 1.0.0 → 1.0.1, the tag set together with P03 ticket 05's check, the APK built by the CI from the tag, `app-version.json` replaced, and a 1.0.0 phone shown 업데이트가 필요합니다. iOS is still built by the Mac owner.
