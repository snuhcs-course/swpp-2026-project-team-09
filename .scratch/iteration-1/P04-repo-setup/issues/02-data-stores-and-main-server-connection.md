# 02: Data stores and main server connection

Parent: [P04 spec](../spec.md)
Status: ready-for-agent
Blocked by: 01 (Main server skeleton)

## What to build

One command starts PostgreSQL, Redis and the main server on a developer's laptop. The main server keeps its schema as migrations in its own database with PostGIS enabled, and it is connected to NestJS messaging over Redis. Its readiness check reports "not ready" when either data store cannot be reached. Together with ticket 01, this is the pattern the socket, worker and match servers follow.

## Acceptance criteria

- [ ] One command starts PostgreSQL, Redis and the main server.
- [ ] The database image is built from the official PostgreSQL 18 image with the PostGIS 3 package added, and it runs without emulation on Apple Silicon. If that fails, the official PostGIS image under emulation is used and the reason is recorded under `## Comments` in this ticket.
- [ ] One PostgreSQL instance holds two databases, one for the main server and one for the match server, each with its own role. The main server's role cannot read or write the match database.
- [ ] Redis 8 is configured never to evict records.
- [ ] Prisma is pinned exactly at 7.10.0. Schema changes are recorded as migrations, and one command brings an empty database up to the current schema.
- [ ] The first migration enables PostGIS in the main database.
- [ ] The feature module note states the identifier rule: every record is identified by a UUID v4 generated by the database. The first table (ticket 06) follows it.
- [ ] The main server is connected to NestJS messaging over Redis, for events and for request and response. The messages themselves belong to P07 and P08.
- [ ] The readiness check reports the database and Redis. It reports "not ready" when either is down, and the liveness check is unaffected.
- [ ] The database and Redis settings are validated at startup and listed in the example settings file.
- [ ] Tests run against a real PostgreSQL and a real Redis started in containers. They cover readiness with both stores up, readiness with one store down, and a spatial function answering in the main database.
